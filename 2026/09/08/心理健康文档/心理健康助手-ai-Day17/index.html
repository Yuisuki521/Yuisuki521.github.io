心理健康助手-ai-Day17

2026/9/8

现在来写后端的实现过程，

1.自定义业务异常处理

API查询后，需要判断用户是否存在，如果user为null，需要告诉前端用户不存在，属于业务异常，需要单独定义，新建exception文件夹新建Exception的BusinessException，添加注解@Getter，添加私有属性code message和data，定义BusinessException方法，然后回到UserService层，抛出异常类；异常还需要在GlobarExceptionHandler中处理异常，在处理中如果异常携带额外信息data，在处理时通过判断e.getData不为空，调用Result.error(三个参数)，为空时最后一个参数为null。

2.验证密码

通过commandDTO.get方法拿到密码(trim())，用inputPassword接收，需要加密算法处理然后比对数据库中的密文密码，通过插件spring-boot-starter-security进行处理，新建config目录创建securityConfig类，添加@Configuration，@EnableWebSecurity，@EnableMethodSecurity，声明方法filterChain，返回类型SecurityFilterChain，通过http .csrf(AbstractHttpConfigurer::disable)禁用csrf保护，因为后面会用到JWT，还需要配置会话管理为无状态
private static final String[] PUBLIC_PATHS = {
“/“,
“/api/test”,
“/api/user/login”,
“/api/user/add”
};包装不需要保护的路径

@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
http
.csrf(AbstractHttpConfigurer::disable)
.sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)) //配置会话管理为无状态
.authorizeHttpRequests(auth -> auth //配置请求授权规则
.requestMatchers(PUBLIC_PATHS).permitAll()//公开路径
.anyRequest().authenticated()//其他需要认证
)
//添加JWT过滤器
.addFilterBefore(jwtAuthticationFilter(), UsernamePasswordAuthenticationFilter.class);
return http.build();
}
回到UserService，
private final BCryptPasswordEncoder passwordEncoder = new BCryptPasswordEncoder();拿到实例后通过passwordEncoder的match方法判断输入密码和数据
库密码，如果比对失败返回业务异常，密码错误。

3.判断用户状态

创建新枚举项，新建文件夹enumClass储存业务层面的枚举项，创建UserStatus添加需要的枚举项，在entity.User中创建方法isActive()，拿到UserStatus的正常的code比对数据库里查到的status,接下来在判断用户状态时直接调用isActive方法不是正常状态则抛出。

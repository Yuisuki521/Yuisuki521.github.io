心理健康助手-ai-Day16

2026/9/7

现在来写后端的实现过程，

1.校验异常

在common文件夹下创建新类GlobarExceptionHandler，两个作用拦截异常和将异常加入到返回的响应体中，使用注解@RestControllerAdvise，在类下指定处理参数校验异常@ExceptionHandler(MethodArgumentNotValidException.class)，定义处理方法handlerException，返回类型Result，传入这个MethodArgumentNotValidException拿一个对象e，处理异常数据用message接收，然后return出来。

2.创建controller层

接下来需要把得到的数据提交给Service层，新建Service文件夹，新建UserService类，添加@Service注解，定义处理方法login接收外部传入的commandDTO，返回类型为Result(在DTO文件夹下新建response文件夹新建UserLoginResponseDTO，在这里定义token roleType和userInfo，加注解data，userInfo为对象结构，给他定义类型为UserDetailResponseDTO(在下面声明类型把userInfo中的数据定义出来，加注解data))。

3.mybatis-plus

找到boot4版本，在pom文件引入；在yml确定配置好数据库的连接；创建文件夹entity存放用户实体类，创建User类，加注解Data，通过@TableName指定user表，定义表中有的id，通过TableId定义id为主键并且他为自增关系，定义username，通过NotBlank让用户名不为空，Size定义长度，通过Pattern限制名字内容，以此类推定义其他内容，回到UserService层；接下来构建查询条件，我们通过对应账号密码构建查询，账号使用User和邮箱为查询条件
LambdaQueryWrapper queryWrapper = new LambdaQueryWrapper<>();
queryWrapper.eq(User::getUsername, commandDTO.getUsername())
.or()
.eq(User::getEmail, commandDTO.getUsername());
类型User为刚才构建的实体类。

通过调用mybatis-plus的API查询，新建Mapper文件夹，新建接口UserMapper，加@Mapper注释，继承BaseMapper，回到Service层，通过@Resource引入将UserMapper导入进来起名userMapper，
User user = userMapper.selectOne(queryWrapper);
System.out.println(user);
在controller测试打印结果，用Resource注入UserService，将之前的返回类型改为UserLoginResponseDTO，启动项目使用apifox测试，控制台成功出现打印结果。

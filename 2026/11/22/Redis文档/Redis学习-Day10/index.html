2026/11/22 学习

Redission

Redisson入门

1.引入依赖：

org.redisson
redisson
3.13.6

2.配置Redisson客户端：
@Configuration
public class RedisConfig {
@Bean
public RedissonClient redissonClient() {
// 配置类
Config config = new Config();
// 添加redis地址，这里添加了单点的地址，也可以使用config.useClusterServers()添加集群地址
config.useSingleServer().setAddress(“redis://192.168.150.101:6379”).setPassword(“123321”);
// 创建客户端
return Redisson.create(config);
}
}

3.使用Redisson的分布式锁：
@Resource
private RedissonClient redissonClient;
@Test
void testRedisson() throws InterruptedException {
// 获取锁（可重入），指定锁的名称
RLock lock = redissonClient.getLock(“anyLock”);
// 尝试获取锁，参数分别是：获取锁的最大等待时间（期间会重试），锁自动释放时间，时间单位
boolean isLock = lock.tryLock(1, 10, TimeUnit.SECONDS);
// 判断释放获取成功
if (isLock) {
try {
System.out.println(“执行业务”);
} finally {
// 释放锁
lock.unlock();
}
}
}

Redission可重入锁原理

Redisson的锁底层用Hash结构存储：key是锁名称，value中的field是线程唯一标识，value是重入次数。
| KEY | VALUE(field) | VALUE(value) |
| lock | threadId | 0 |

可重入锁流程：
A([开始]) –> B{判断锁是否存在}
B – 否 –> C[获取锁并添加线程标识]
C –> D[设置锁有效期]
B – 是 –> E{判断锁标识是否是自己}
E – 否 –> F[获取锁失败]
E – 是 –> G[锁计数+1]
G –> D
D –> H[执行业务]
H –> I{判断锁是否是自己}
I – 否 –> J[锁已释放]
I – 是 –> K[锁计数-1]
K –> L{判断锁计数是否为0}
L – 否 –> M[重置锁有效期]
M –> H
L – 是 –> N[释放锁]

Redisson分布式锁原理

获取锁流程

A([开始]) --> B[尝试获取锁]
B --> C{判断ttl是否为null}
C -- 是 --> D{leaseTime是否为-1}
D -- 是 --> E[开启watchdog]
E --> F[返回true]
C -- 否 --> G{判断剩余等待时间是否大于0}
G -- 否 --> H[返回false]
G -- 是 --> I[订阅并等待释放信号]
I --> J{判断等待时间是否超时}
J -- 否 --> B
J -- 是 --> H

获取锁失败时不是立即放弃，而是订阅锁的释放信号后重试等待，直到超过最大等待时间为止。leaseTime=-1表示没有指定释放时间，由watchdog自动续期。

释放锁流程

A([开始]) --> B[尝试释放锁]
B --> C{判断是否成功}
C -- 否 --> D[记录异常]
C -- 是 --> E[发送释放消息]
E --> F[取消watchdog]
F --> G([结束])
D --> G

释放锁成功后需要：1.发布释放消息通知等待队列里的线程；2.关闭watchdog，避免锁被错误续期。

Redisson分布式锁主从一致性问题

问题:Redis主从同步是异步的：Java应用通过SET lock thread1 NX EX 10获取锁成功，key还没同步到Slave时Master就宕机，Slave晋升为新Master，但新Master上没有这个锁key，其他线程又能获取到同一把锁，锁就失效了。集群中每个Node都存在同样的问题。

解决方案:在Redis集群中，让客户端同时向多个Redis节点尝试获取锁，只有在过半节点（如5个节点里至少3个）都获取锁成功时，才认为整体获取锁成功。释放锁时需要对所有节点依次执行释放，避免锁残留在节点上。这样即使少数节点主从切换丢失了锁，其他节点上的锁仍然存在，保证整体的安全性。

RedLock实现思路

获取所有Redis节点的连接
依次向每个节点发送SET key value NX EX timeout命令
统计成功的节点数，过半则认为获取锁成功，否则依次释放已获取的锁
释放锁时，遍历所有节点执行释放脚本，确保每个节点上的锁都被清理

2026/11/4 学习

缓存

缓存是数据交换的缓冲区，是存贮数据的临时地方，一般读写性能较高

添加Redis缓存

缓存作用模型

A[客户端] -- 请求 --> B[Redis]
 B -- 命中 --> A
 B -- 未命中 --> C[数据库] -->A[客户端]
C -- 写缓存 --> B

根据id查询商铺缓存的流程

A([开始]) --> B[提交商铺id]
B --> C[从Redis查询商铺缓存]
C --> D{判断缓存是否命中}
D -- 未命中 --> E[根据id查数据库]
 E --> F{判断商铺是否存在}
 F -- 存在 --> G[将商铺数据写入Redis]
 G --> H[返回商铺信息]
 F -- 不存在 --> I[返回404]
D -- 命中 --> H
H --> Z([结束])
I --> Z

缓存的更新策略

虽然缓存可以提高查询效率，但是缓存数据是静态的，不能及时更新。为了保持缓存数据的实时性，会有内存淘汰，超时剔除和主动更新三种方法。
内存淘汰不用自己维护利用Redis的内存淘汰机制，当内存不足自动淘汰部分数据，下次查询时更新缓存，没有维护成本但是一致性差。
超时剔除是添加TTL时间，到期后自动删除缓存，下次查询时更新缓存，一致性一般维护成本低。
主动更新是编写业务逻辑，在修改数据库时更新缓存，一致性好维护成本高。

缓存更新策略的最佳实践方案

低一致性需求：使用Redis自带的内存淘汰机制
高一致性需求：主动更新，并以超时剔除作为兜底方案
读操作：
缓存命中则直接返回
缓存未命中则查询数据库，并写入缓存，设定超时时间
写操作：
先写数据库，然后再删除缓存
确保数据库与缓存操作的原子性
